# SmartMeet（产品需求与研发说明）

基于 **Qt 6 + FFmpeg + OpenCV + ZLMediaKit** 的多平台视频会议与远程教学系统（定位：类腾讯会议）。

本文件用于统一：
- 产品目标与边界
- 架构与模块拆分
- 当前已实现能力
- 本地/云端部署流程

## 目标
- 交付 Windows `.exe` 客户端，支持 2-6 人远程视频会议。
- 使用 ZLMediaKit 作为媒体服务，先跑通本地稳定链路，再演进至标准 WebRTC/SFU。
- 模块化设计，低耦合、高内聚，后续可扩展到教学与协作场景。
- 作为面试级项目，覆盖音视频、网络、UI、并发、权限控制、部署文档等完整能力。

## 总体架构

### 客户端（Qt 6）
- 采集：摄像头、麦克风、屏幕（FFmpeg / QMediaDevices / QScreen）。
- 处理：OpenCV 图像处理（美颜、背景虚化等，当前为占位）。
- 传输：当前为 **RTMP 推拉 + WebSocket 信令**；目标演进到 WebRTC。
- UI：Qt Widgets + Qt Designer，多视频宫格 + 焦点放大。

### 服务端（云端/本地）
- ZLMediaKit：音视频流发布与分发（当前主用 RTMP）。
- STUN/TURN（coturn）：公网穿透（WebRTC 阶段需要）。
- 自建信令服务（当前为 `signalTest`）：房间、成员、角色、控制指令。

### 当前链路（已落地）
1. 客户端连接信令并加入房间。
2. 客户端开始会议后向 ZLM 推流：`rtmp://127.0.0.1/live/{room}_{user}`。
3. 信令广播成员状态（pub/audio/video/role）。
4. 客户端按成员并发拉流，宫格展示，多路中仅焦点流输出音频。
5. 主持人/联席主持通过信令控制成员麦克风、摄像头、踢出、角色管理。

- H264/AAC 编码。
- RTMP 推流到 ZLM。

- 本地 AV 录制（音画同步）。

  - 多路并发宫格。

#### M3 详细范围（下一开发模块）
目标：实现可用于真实会议的“消息协作基础能力”。

功能清单（必须）：
- 房间内文本消息发送/接收（群聊）。
- 消息时间戳（发送时间）与发送者标识。
- 系统消息（成员加入/离开、主持控制动作）。
- 消息滚动区与输入框（Enter 发送，Shift+Enter 换行）。
- 本地消息缓存（至少当前会话内可回看）。
- 信令协议扩展（新增 `chat` 类型，含 `room/user/stream/content/ts/msg_id`）。

功能清单（可延期到 M3.1）：
- 消息历史持久化（SQLite）。
- 表情消息（emoji）。
- 撤回/引用。

不在 M3 范围（禁止插入）：
- 富文本编辑器。
- 文件传输。
- 群公告、@全体等复杂 IM 功能。

M3 验收标准：
- 双实例同房间连续发送 100 条消息，显示顺序正确，UI 不冻结。
- 长文本与空消息处理正确（空消息禁止发送）。
- 断开后重连，系统消息与成员状态不冲突。
- 不影响现有音视频链路与主持人管理能力。

#### M4 详细范围（屏幕共享 + 白板 + OpenCV 美颜 V1）
目标：让“会议协作”从聊天升级到可视化协作，并落地第一版可用美颜能力。

功能清单（必须）：
- 单路屏幕共享发布（同一时刻一个共享源）。
- 共享流在成员列表/宫格中有明确标识（例如 `[共享]`）。
- 主持人可停止他人共享（权限复用现有控制模型）。
- 基础白板：画笔、清空、颜色切换。
- 白板最小同步：同房间成员可看到绘制结果。
- OpenCV 美颜 V1：
  - 提供“美颜开关 + 强度参数”（0-100）；
  - 至少包含 2 项基础处理：磨皮（双边滤波或等效）+ 亮度/肤色增强；
  - 作用链路为“本地预览 + 推流画面”一致；
  - 功能入口复用底部美颜菜单，不新增破碎化按钮。

功能清单（可延期到 M4.1）：
- 局部撤销重做。
- 激光笔、矩形、箭头等高级标注。
- 美颜高级参数（锐化、降噪、肤色保护曲线）。
- 虚拟背景（分割/模糊）初版。

M4 验收标准：
- 共享 10 分钟持续稳定，接收端不卡死。
- 白板基础绘制在双实例可见，延迟可接受。
- 不破坏 M3 聊天功能与 M2 音视频能力。
- 在当前开发机 640x480@30 场景下，开启美颜后可持续运行，不出现明显卡顿/花屏/音画不同步。

#### M5 详细范围（登录与权限）
目标：把“会议工具”升级到“可管理系统”。

功能清单（必须）：
- 用户注册/登录（至少本地 SQLite）。
- 密码安全存储（哈希，不明文）。
- 基础角色模型：普通成员/主持人/管理员。
- 会议记录归档：房间号、起止时间、成员列表。
- 面试版云端部署基线：**1 台 Linux 云服务器部署 ZLMediaKit + signal 服务 + SQLite 数据文件**。
- 数据库策略：先用 SQLite 跑通上线；代码层预留 `QSQLITE/QMYSQL` 可切换接口，后续再迁移 MySQL。

功能清单（可延期到 M5.1）：
- 多租户组织结构。
- 审计后台界面。
- MySQL / 云数据库 RDS 迁移脚本与灰度切换。

M5 验收标准：
- 登录态稳定，异常退出后可恢复。
- 权限动作有日志可追踪。
- 无未鉴权敏感接口。

#### M6 详细范围（稳定性与弱网）
目标：提升抗抖动能力与工程质量，准备公网化。

功能清单（必须）：
- 断线重连机制（信令、拉流、推流分开处理）。
- 基础弱网降级（分辨率/帧率优先级策略）。
- 关键线程健康检查与日志分级。
- 30 分钟压力回归脚本（本地双实例 + 假人流）。
- OpenCV 美颜 V2 性能优化：
  - 人脸 ROI 处理（避免全帧重算）；
  - 帧间平滑与参数防抖（避免画面闪烁）；
  - 在弱网与高负载下自动降级美颜强度（优先保通话稳定）。

M6 验收标准：
- 连续运行 30 分钟无崩溃。
- 网络抖动下可自动恢复，不需手工重启客户端。
- 开启美颜情况下仍满足会议稳定性，不引入线程阻塞或明显拉流抖动。

#### M7 详细范围（WebRTC 主链路迁移）
目标：把现有 RTMP 稳定版能力等价迁移到 WebRTC 主链路。

功能清单（必须）：
- WebRTC 发布/订阅最小闭环。
- STUN/TURN 接入与 NAT 场景验证。
- 与现有房间信令和主持权限模型兼容。
- 保留 RTMP 作为回退路径（至少开发阶段保留）。

M7 验收标准：
- 2 端 WebRTC 通话稳定可用。
- 主持控制、成员状态、聊天功能链路完整。
- RTMP/RTC 可按配置切换。

## 关键约束
- FFmpeg 7.1.1 新版 API（`ch_layout` 替代旧 `channel_layout`）。
- 模块接口清晰、可替换、低耦合。
- CMake 构建，依赖分层管理。
- 任何线程停机路径必须可重复调用且不崩溃。
- 主持人控制必须服务端二次鉴权，客户端不做“信任假设”。
- UI 布局优先在 `mainwindow.ui`（Qt Designer）维护；仅动态宫格等必要场景允许代码动态创建控件。
- 源码与文档统一使用 UTF-8，避免中文乱码回归；日志中文建议 `QStringLiteral`。
- 信令协议字段新增必须向后兼容（旧客户端至少可忽略未知字段而不崩溃）。

## 网络方案（WebRTC 方向）
- 信令：WebSocket/HTTP（交换 SDP/ICE 或房间控制）。
- STUN/TURN：解决公网穿透与弱网问题。
- ZLMediaKit REST API：房间与流管理。
- SFU：一人推流，多人订阅。

> 现状说明：当前为 RTMP + WebSocket 信令稳定版。后续可在此基础平滑演进到 WebRTC（复用房间与权限模型）。

## 非功能性指标（SLO）
- 入会体验：点击“连接信令”到收到成员列表，目标 `<= 3s`（本地环境）。
- 首帧时延：点击开始拉流到首帧显示，目标 `<= 5s`（本地环境）。
- 焦点切换：双击切焦点到主画面更新，目标 `<= 1s`。
- 音画同步：主观可接受，目标 A/V 偏差 `<= 150ms`。
- 稳定性：连续运行 30 分钟无崩溃、无线程析构错误。
- 资源占用：在当前开发机下不出现长期 100% CPU 占满导致 UI 无响应。

## 信令协议治理（强制）
- 协议信封统一包含：`type`、`room`、`stream`、`ts`（时间戳）、`ver`（协议版本，建议从 `1` 开始）。
- 客户端必须容忍未知字段：可忽略，不得崩溃。
- 服务端是角色与权限唯一可信源；客户端角色仅作展示，不可作为授权依据。
- 控制类消息（`cmd`）建议逐步引入 `req_id/ack`，便于审计和失败重试。
- 聊天模块（M3）开始后，消息 ID 必须全局唯一（至少房间内唯一）。

### 信令消息最小字段规范（V1）
| 消息类型 | 必填字段 | 说明 |
|---|---|---|
| `join` | `type, room, user, stream, audio, video, pub, ts, ver` | 入会注册成员状态 |
| `leave` | `type, room, stream, ts, ver` | 离会通知 |
| `update` | `type, room, stream, audio, video, pub, ts, ver` | 状态同步（麦克风/摄像头/推流） |
| `members` | `type, room, members, ts, ver` | 服务端广播成员快照 |
| `cmd` | `type, room, to, action, from, ts, ver` | 主持控制类指令 |
| `ctrl` | `type, to, action, by, ts, ver` | 服务端下发控制结果 |
| `chat`（M3） | `type, room, user, stream, content, msg_id, ts, ver` | 聊天消息 |
| `ack`（可选） | `type, req_id, ok, code, msg, ts, ver` | 指令确认/失败原因 |

## 本地启动与联调步骤（详细）

### 1) 启动 ZLMediaKit
确保 RTMP 端口可用（默认常见为 1935）。

### 2) 启动 signalTest
在 `D:\QTcoding\signalTest` 运行，默认监听：

### 3) 启动 SmartMeet（建议双实例）
- 实例 A、实例 B 输入同一房间号。

### 4) 主持控制验证
- 主持人右键成员：静音/恢复、关/开摄像头、踢出。

- 主持人设置/取消联席主持。
- 联席主持尝试管理主持人（应被拒绝）。

### 5) 录制验证
- 开始 AV 录制 -> 停止录制。
- 检查输出文件是否同时包含音频和视频。

## 服务器部署（建议阿里云）
建议配置（2-6 人会议）：
- 2 核 4G / 5Mbps 起步（人数增加时提高带宽）。
- Linux（CentOS/Ubuntu）。
- 固定公网 IP + 域名（推荐）。

重点配置：
- ZLMediaKit：
  - 打开 WebRTC/SFU（目标阶段）。
  - 设置 `externIP`。
  - 配置 RTC 端口（UDP 端口或端口段）。
- 防火墙/安全组：
  - 放行 TCP（80/443/1935/554/8000 等按配置）。
  - 放行 UDP（RTC 端口或端口段）。
- STUN/TURN（coturn）：
  - 公网环境建议开启，提升 NAT 穿透成功率。

## 常见问题排查
- `open_input: Immediate exit requested`：通常是拉流会话被 stop 标记或重复切换冲突，先结束会议再重试。
- `open_input: Operation not permitted`：流不存在、地址错误或权限/连接问题，先查 ZLM 是否存在该 stream。
- `QThread: Destroyed while thread is still running`：线程回收路径未等停；已在当前版本重点修复，若复现需保留日志定位。
- `QWindowsWindow::setGeometry...`：输入框尺寸警告，通常不影响核心功能。
