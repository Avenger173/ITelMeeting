# S6 进入前盘点清单

适用阶段：`S5 已完成，准备进入 S6(OpenGL 渲染升级)`  
当前基线：`RTMP + Go 信令 + MySQL + Qt Widgets`

---

## 1. 盘点目标

- 确认当前版本已具备进入渲染层升级的稳定基线。
- 明确 S6 只替换“显示与渲染路径”，不碰信令协议、房间模型、数据库模型。
- 在进入 OpenGL 前，锁定必须保留的行为与不可回归项。

---

## 2. 当前基线确认

进入 S6 前，以下状态应成立：

- 云端信令服务为 `smartmeet-go-signal`
- 云端监听端口为 `9001`
- 旧 `smartmeet-signal` 已停用并 `mask`
- 云端数据库为 MySQL，`users` 与 `meeting_events` 正常写入
- 当前客户端默认媒体链仍为 RTMP

---

## 3. 功能回归清单

以下功能在进入 S6 前必须全部通过：

### 3.1 会议信令
- 登录/注册正常
- 入会/离会正常
- 成员列表同步正常
- 聊天正常
- 白板绘制、撤销、清空、锁定正常
- 主持控制正常
- 转主持/联席主持正常
- 断线重连正常

### 3.2 媒体链路
- 开始会议可正常推流
- 宫格可正常拉流
- 焦点流切换正常
- 双击焦点放大正常
- 焦点音频输出正常
- 屏幕共享可开启/停止
- 共享切回摄像头后不会长期慢速卡顿

### 3.3 本地能力
- 本地截图正常
- 本地录制正常
- 非推流端截图/录制行为符合当前设计
- 关闭主窗口时无崩溃、无 Runtime 弹窗

---

## 4. 进入 S6 前必须记录的已知问题

这些问题不一定要先修，但必须明确记录，避免 OpenGL 改造时被误判为新回归：

- 美颜自然度不足，高强度瘦脸仍不理想
- 共享与摄像头切换后偶发短时卡顿
- 局部 UI 在分辨率变化时仍会挤压
- 多路渲染下 CPU 占用仍偏高

---

## 5. S6 的技术边界

S6 允许改动：

- 远端视频显示控件
- 焦点流与宫格渲染管线
- 画面缩放、纹理上传、刷新策略
- 渲染线程/显示性能相关代码

S6 暂不允许改动：

- Go 信令协议字段
- 房间状态模型
- MySQL 表结构
- 主持控制业务规则
- 聊天/白板消息结构
- RTMP 推流/拉流协议本身

---

## 6. S6 成功标准

进入 S6 后，至少要达到：

- 多路画面显示更稳定
- 焦点放大更平滑
- CPU 占用较当前版本明显下降
- 不引入新增崩溃、线程残留、严重音画不同步
- 信令与业务行为保持完全兼容

---

## 7. 建议执行顺序

1. 先完成一轮当前版本全量回归并记录结果  
2. 记录当前 CPU、内存、切流与共享时的基线表现  
3. 明确 OpenGL 第一阶段只做“远端视频渲染替换”  
4. 第一阶段通过后，再考虑本地预览与美颜链是否纳入 OpenGL

---

## 8. 退出条件

满足以下条件后，可正式进入 S6 开发：

- 本清单第 3 节全部通过
- 第 4 节问题已知且可复现
- 当前线上 Go 信令稳定运行
- README 已更新为当前真实部署状态
