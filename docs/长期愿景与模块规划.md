# 音视频工作台长期愿景与模块蓝图

定位：面向交流、创作与学习的桌面音视频工作台。用户在首页按需安装功能，各模块独立使用，也能组合完成任务。

先交付面向课题组组会的「智能会议协作」首模块，再从下列候选模块中选择扩展。本表是长期愿景，不是一次性开发清单；当前范围以 [首模块计划](./毕业设计首模块计划.md) 为准。

## 1. 软件最终形态

- **首页**：模块卡片、最近文件、进行中的任务、设备状态与全局助手。
- **模块中心**：下载、更新、启用、停用、卸载；显示依赖、安装空间和运行要求。
- **任务中心**：统一查看转码、转写、录制和 Agent 任务，支持取消、重试和结果定位。
- **资源中心**：统一索引媒体、字幕、纪要与用户导入资料，按模块和会话隔离访问范围。

首模块随软件安装；卸载功能与删除用户数据分别操作。模型按需下载，共享依赖在仍被使用时保留。

## 2. 候选功能模块

难度为相对当前项目的工程预估；「低投入」指可优先使用现有电脑，仍有开发、存储或带宽成本。「API」表示费用随调用量产生，「GPU 可选」不代表所有效果都能在 CPU 实时运行。

### 基础与高频工具

| 编号与模块 | 代表功能与实际用途 | 难度与投入 |
|---|---|---|
| M01 智能会议协作 | 课题组组会、共享白板、共享转写与聊天历史、个人文字 Agent、可编辑纪要 | 中高；首模块，复用现系统，AI 按需调用 |
| M02 录屏与即时回放 | 窗口/区域录制、摄像头画中画、保存最近一段操作；用于教程和问题复现 | 中；本地运行，关注磁盘与编码负载 |
| M03 播放器与媒体库 | 本地/网络媒体播放、倍速、字幕、书签、断点续播与文件归类 | 中；低投入 |
| M04 媒体批处理 | 转码压缩、封装转换、裁切拼接、音轨提取、批量水印与任务队列 | 中；CPU 优先，硬件编码可选 |
| M05 字幕与转写工作室 | 录音/录像转写、字幕校对、时间轴调整、SRT/VTT 导出与字幕烧录 | 中；轻量模型或 API |

### 内容制作与协作

| 编号与模块 | 代表功能与实际用途 | 难度与投入 |
|---|---|---|
| M06 录音与播客工作室 | 分轨录音、基础剪切、降噪、响度调整、背景音乐与成品导出 | 中高；本地 CPU，复用音频引擎 |
| M07 直播导播台 | 场景编排、多源合成、混音、字幕水印、平台推流；服务多人访谈和讲座 | 高；关注 GPU、编码与上行带宽 |
| M08 课堂与讲座工作台 | 课程资料、举手互动、板书录制、课后问答和学习总结 | 中高；复用会议、转写与资料服务 |
| M09 同步观看与远程评审 | 同步播放、暂停讨论、时间点批注；用于作品评审和教学分析 | 中高；媒体权限与播放同步需单独设计 |
| M10 多机位录制 | 手机/摄像头/会议流分轨保存、统一时间信息、会后选镜头 | 高；多设备可选，磁盘和同步成本较高 |

直播导播既能独立开播，也能接入授权会议流：多人画面、共享内容和声音合成后输出一条节目流。观众使用现有平台观看，先不建设公众直播平台。场景组织参考 [OBS 官方指南](https://obsproject.com/kb/OBS-Studio-Overview)。

### AI 与个人生产力

| 编号与模块 | 代表功能与实际用途 | 难度与投入 |
|---|---|---|
| M11 音视频知识库 | 检索历史转写、纪要和导入资料，回答时关联来源及媒体时间点 | 中高；本地索引，LLM 可走 API |
| M12 语音陪练与模拟面试 | 语音角色对话、专业提问、回答复盘与表达建议 | 中；复用转写与 LLM，另接 TTS，按需调用 |
| M13 人像与画质增强包 | 美颜、虚拟背景、自动取景、隐私区域遮挡；供会议/录屏/导播调用 | 中高；轻量功能先行，GPU 可选 |
| M14 翻译与配音工作室 | 字幕翻译、普通 TTS 配音、双语音轨和时间对齐 | 中高；API 或本地模型，先做离线任务 |
| M15 Agent 自动化工作台 | 用自然语言组织「转写→检索→整理→导出」任务，展示工具执行与失败重试 | 中高；复用公共工具与状态管理 |

M01 的个人会议 Agent 与 M15 的跨模块 Agent 共享工具接口与执行引擎，按用户和会话隔离数据。M01 当前只做文字问答；机器人语音参会、主动发言和停止播报留作后续独立评估，不是首模块验收要求。

## 3. 模块如何协作

- **课题组讨论**：M01 开会 → M11 保存可检索知识 → M15 整理行动项。
- **教程制作**：M02 录屏 → M05 校对字幕 → M04 压缩导出。
- **多人公开讲座**：M01 提供嘉宾流 → M07 导播制作 → M06/M10 保存独立素材。
- **学习与求职**：M11 导入资料 → M12 语音陪练 → M15 汇总薄弱点。

用户可以只安装其中一个业务模块；模块之间通过能力接口连接，避免强制安装整套软件。

## 4. 高内聚与低耦合

| 层次 | 负责内容 |
|---|---|
| 应用外壳 | 首页、模块安装管理、公共设置和任务导航 |
| 业务模块 | 各自的界面、业务状态、任务和数据访问规则 |
| 媒体能力 | 设备占用、采集、音画同步、编解码、合成混音、录制与传输 |
| AI 能力 | ASR/TTS/LLM 适配、视觉模型、检索与 Agent 工具执行 |

功能包携带版本、入口、接口版本、依赖与校验信息。重服务优先独立进程，按需启动并监测状态；[QProcess](https://doc.qt.io/qt-6/qprocess.html) 可用于进程管理。界面扩展另设接口，不要求所有模块都通过 DLL 热卸载。

控制命令走 HTTP/WebSocket 或本地 IPC；媒体帧走有界原生缓冲，跨进程时再评估管道或共享内存。采集设备和共享服务统一管理生命周期，避免模块争抢设备和重复启动模型。

## 5. 投入与实施顺序

1. **首模块交付期**：只交付 M01、简单首页和必要的公共接口；先完成 WebRTC 迁移，再开发共享记录、个人文字 Agent 与纪要，范围见 [首模块计划](./毕业设计首模块计划.md)。
2. **低成本扩展期**：从 M02、M04、M05、M19 中选一到两个，验证真实模块安装、更新与卸载。
3. **生产力完善期**：根据使用频率增加 M03、M06、M11、M12、M15，形成可复用工作流。
4. **复杂媒体期**：评估 OpenGL 合成、硬件编解码和带宽，再推进 M07、M09、M10、M16。
5. **按需探索期**：M08、M13、M14、M17、M18、M20 以真实需求和资源条件决定，允许长期搁置。

优先普通电脑与现有云服务，模型按需加载，API 设置用量限额。首模块当前优先迁移 WebRTC；SRT、HLS、新编码器和更强模型在对应场景中评测后引入。保留标准媒体文件、版本化接口及供应商适配层，不以协议或模型数量作为完成指标。
