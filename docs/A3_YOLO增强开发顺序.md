# A3 YOLO 增强开发顺序

## 1. 目标

A3 的目标不是“随便接个检测模型演示一下”，而是把 `YOLO 检测` 做成一个：

- 可独立验证
- 可逐步接入会议场景
- 不会一上来就打乱 Qt 主链
- 方便后续与 `S6 / A5` 对接

当前已经完成到：

- Python `/detect`
- YOLO ONNX 模型验证
- Qt 本地预览调试叠框

这一阶段仍然只限本地预览调试，不进入推流主链，不进入远端画面。

---

## 2. 当前推荐路线

当前推荐路线：

- `ONNX Runtime + 轻量 YOLO 检测模型`

第一版默认模型约定：

- `yolo11n.onnx`

推荐原因：

- 更贴近常见招聘关键词：`YOLO / ONNX / ONNX Runtime`
- 方便后续从 Python 演进到 C++ 或 OpenGL 叠加
- 和 A2 的 ONNX 路线一致，整体更统一

---

## 3. 阶段顺序

### A3-P1：Python `/detect`

先在 `pythonAiService` 增加：

- `POST /detect`

输入：

- 一张 base64 图片

输出：

- 检测框
- 类别 ID
- 类别名
- 置信度

退出标准：

- `/healthz` 能返回 `detect_ready`
- `/detect` 能稳定返回检测结果

### A3-P2：模型选择与阈值校准

重点确定：

- 最终使用的轻量模型
- `conf_threshold`
- `iou_threshold`
- 目标类别是否需要做过滤

退出标准：

- 单张图片检测结果可用
- 误检率和漏检率在可接受范围

### A3-P3：Qt 侧调用层

新增一个很薄的客户端调用层，例如：

- `AiDetectionClient`

职责：

- 调 `/detect`
- 处理超时
- 丢弃过期结果
- 把检测框结果回传给 UI

退出标准：

- Python 服务慢或挂掉时，客户端不阻塞

### A3-P4：会议场景接入

第一版优先考虑这两类场景：

1. 本地摄像头演示模式
2. 屏幕共享辅助识别模式

当前已完成其中的“本地摄像头演示模式（调试叠框）”。
不建议下一步直接对所有远端流做检测。

退出标准：

- 能在至少一个真实会议场景中看到检测结果
- 不影响主会议功能可用性

### A3-P5：收口与回归

重点回归：

- 开会
- 聊天
- 白板
- 共享
- A2 虚拟背景
- A3 检测同时开启时的负载情况

---

## 4. 当前第一版不做

- 不做多人多路同时检测
- 不做 OpenGL 叠框
- 不做远端所有视频流的全量检测
- 不做 GPU 推理
- 不做自动控制主持逻辑

---

## 5. 与 S6 / A5 的关系

- `A3` 可以先于 `S6`
- `S6` 是渲染层升级，不等于 A3
- `A5` 才是 AI 结果与 OpenGL 的叠加阶段

当前顺序仍然是：

1. A2 已完成第一阶段
2. A3 先做服务端检测能力
3. 再接入 Qt 本地预览调试叠框
4. 再决定是否把检测结果升级为正式客户端功能
5. S6 继续后置
