# 毕业设计首模块计划

建议题目：**基于语音交互智能体的实时音视频协作系统的设计与实现**。

软件定位：音视频工作台的首个内置模块「智能会议协作」。面向小组讨论、课题研讨和远程答辩，重点完成 AI 机器人参会与会议纪要。

## 1. 本次交付

| 内容 | 范围 |
|---|---|
| 首页与模块入口 | 展示并进入内置会议模块，支持退出与停用；在线安装卸载后续完善 |
| 会议基础 | 将媒体主链由 RTMP 迁移为 WebRTC + SFU；保留多人会议、共享、白板、会控、录制及现有音视频增强 |
| 会议机器人 | 主持人启用，成员可见；点名或按钮提问后，结合会议上下文给出文字和语音回答，可停止播报 |
| 会议纪要 | 使用同一份转写，生成议题、决策、待办和未决问题，支持编辑与导出 |

直播导播、视频片段导出、录像章节跳转与复杂剪辑均不作为本次必做项。原有录制继续保留，纪要不要求先保存整场录像。

## 2. 一个 Agent 承担两种任务

共享链路：`参会者音频 → VAD/语音转写 → 带成员与时间信息的会议记录 → Agent → 语音回答 / 纪要`。

- 复用同一个 Agent 与会议上下文，分别处理会中问答和会后整理，无需先搭多 Agent 系统。
- 工具先提供「读取会议上下文、查询历史转写、保存纪要与待办、请求语音播报」；模型选择工具，程序校验参数、权限并记录执行结果。
- 回答优先引用讨论内容；建议与已达成的决策分开。待办负责人、截止时间未明确时标记待确认。
- 默认被点名才发言；经主持人开启后可在议题结束时小结。私人问答与全员可见的机器人回答分开。

## 3. 实现难点与资源控制

主要难点是 WebRTC 原生客户端集成、多人音频接入、语音结束判断、TTS 入会和发言调度。按已认证成员身份归属音轨，机器人音轨排除出触发输入；起步使用耳机，验证自采集下的回声处理。语音轮次控制参考 [LiveKit 官方说明](https://docs.livekit.io/agents/logic/turns/)。

保留 Qt6、FFmpeg、Go、MySQL、Python/FastAPI 与已有视觉/降噪能力；新增 WebRTC 原生 SDK、SFU、ASR、TTS、LLM 工具调用和任务状态管理。先验证自托管 LiveKit 与 C++ SDK，ZLMediaKit WebRTC 作为备选。模型按本机资源评测，LLM 复用 API；RTC SDK 对编译工具与 C++ 标准的要求在原型阶段确认。

## 4. 开发顺序与验收

1. 恢复最小基线，在本地 Linux 验证 WebRTC 双端原型并完成媒体迁移。
2. 回归现有功能，建立首页与模块入口，分离会议、媒体和 AI 职责。
3. 接入分用户音频转写，验证上下文问答及纪要。
4. 接入工具执行与状态反馈，再让 TTS 以机器人音轨入会。
5. 完成停止播报、异常降级和联合演示，记录延迟、资源占用与工具执行结果。

验收场景：两名成员讨论方案，机器人被点名后通过工具读取会议记录并语音回应；会后保存可编辑纪要。AI 故障时会议仍能继续。S6/OpenGL 按显示瓶颈另行安排，不作为语音机器人前置条件。
