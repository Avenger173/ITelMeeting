# 毕业设计首模块计划

题目：**面向课题组组会的智能音视频协作系统的设计与实现**。

软件定位：音视频工作台的首个内置模块「智能会议协作」。本阶段聚焦小规模课题组例行组会，开发顺序见 [开发与部署计划](./毕业设计开发与部署计划.md)。以下新增能力均为计划，当前实现边界见 [主 README](../README.md)。

## 1. 命题内容及要求

课题组组会是师生交流研究进展、讨论问题和安排后续任务的重要方式。在远程组会中，汇报内容与讨论信息较为分散，临时离会或迟到的成员难以及时了解讨论进展，会后也容易出现结论遗漏、任务分工不明确等问题。

本课题在已有音视频会议原型的基础上，面向小规模课题组例行组会，开发一套智能音视频协作系统。系统通过会议转写、上下文问答和智能纪要，辅助成员了解讨论进展、回顾会议结论与明确后续任务。系统需实现以下主要功能：

1. **组会交流与协作**：采用成熟的 WebRTC SDK 和媒体转发服务，实现成员加入会议、多人音视频交流、汇报材料共享、文字讨论与主持控制，满足学生汇报和教师点评的基本需求。
2. **讨论记录与进展回顾**：主持人开启会议转写后，后台持续记录参会者发言，关联成员身份和时间信息，并保存会议聊天记录。已授权成员中途加入或重新连接后，可以查询此前已保存的会议记录，并按需生成阶段摘要，了解讨论进展。
3. **会中个人智能体辅助**：成员通过独立的个人助手窗口进行文字提问，智能体调用会议记录查询等工具，结合已授权的会议上下文，梳理讨论分歧、解释已讨论内容或提供建议，并关联相关发言及时间信息。个人问答默认仅对当前用户可见；模型建议与会议已达成的结论分别标明。
4. **会议结论与任务整理**：根据讨论记录生成包含研究进展、主要问题、已达成决策、待办事项和未决问题的会议纪要，支持人工修改、保存与导出。对于尚未明确的负责人、截止时间或结论，标记为待确认。

## 2. 交付边界

- 保留并回归已有白板、录制、美颜、ONNX 虚拟背景、YOLO 本地预览等能力；RNNoise 本地改动另行提交与复测。上述能力复用现有实现，不另开复杂视觉算法开发。
- AI 仅提供文字问答与纪要；语音合成、主动发言、停止播报、数字人及复杂语音轮次控制留作后续可选扩展。正常参会者音视频交流保留。
- 会议公开记录共享，个人问答按用户隔离；转写不依赖某个成员的客户端持续在线。转写开启前或服务故障期间未采集的内容不承诺补回。
- 纪要基于文字记录生成，不要求保存整场录像或导出音视频片段；原有录制独立保留。暂不建设完整任务管理系统。
- 首页提供内置会议入口；直播导播、模块在线安装卸载、S6/OpenGL 与 A5 后置。

## 3. 所需条件

1. 掌握 C++ 与 Qt 客户端开发技术，熟悉多线程、信号槽、异步事件处理和资源生命周期管理，能够使用 CMake 构建项目。
2. 熟悉音视频采集、编解码、传输与播放流程，能够使用 FFmpeg 和成熟的 WebRTC SDK；了解 SFU、ICE/STUN/TURN，以及音画同步和网络适应的基本原理。
3. 掌握 Go、WebSocket 与 MySQL 的基本应用，能够开发业务服务，实现身份认证、房间状态同步、权限控制、会议记录存储与历史查询。
4. 能够使用 Python、FastAPI 接入语音识别及大语言模型服务；理解智能体的工具调用、上下文检索和任务状态管理，能够使用现成模型或接口完成相关功能集成。OpenCV 与 ONNX Runtime 用于复用已有视觉能力。
5. 掌握 Linux 服务器应用部署方法，熟悉 Git 版本管理和基本 DevOps 流程；具备自主阅读原始技术文档、定位问题及编写规范软件开发文档的能力。

实现重点是原生 RTC 接入、共享记录的可靠保存与补取、按权限检索及受控工具调用。编解码、媒体传输和语音识别复用成熟组件，不自行训练模型或重写协议栈。
